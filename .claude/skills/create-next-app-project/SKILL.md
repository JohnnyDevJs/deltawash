# Create Next.js App

## Purpose

Create a new Next.js application using the latest stable version of Next.js and configure ESLint and Prettier with the project's required standards.

The application name must always be the name of the current root directory.

The Next.js application must always be installed directly inside the current root directory. Never create another directory for the application.

---

## Mandatory Rules

1. Always determine the application name from the current root directory name.
2. Never ask the user for an application name when the current root directory name is available.
3. Never create a new directory for the Next.js application.
4. Always install the Next.js application directly in the current root directory using `.`.
5. Always use the latest stable version of Next.js.
6. Always use TypeScript.
7. Always use App Router.
8. Always use the `src/` directory.
9. Always enable Tailwind CSS.
10. Always install ESLint.
11. Always configure Prettier.
12. Always install all ESLint and Prettier dependencies defined by this skill.
13. Always create the application inside the current root directory.
14. Do not create an additional workspace, monorepo, or parent directory.
15. Use the package manager already used by the current project when detectable.
16. If there is no existing package manager configuration, use `pnpm`.
17. Never modify the ESLint or Prettier configuration defined by this skill unless explicitly requested by the user.
18. Do not add comments to generated application source code.
19. All generated code, filenames, variables, functions, and technical identifiers must be in English.
20. Remove the default `README.md` generated by Next.js from the project root.

---

## Step 1 — Determine Application Name

Before running installation commands, determine the name of the current root directory.

Use the current root directory name as the application name.

Example:

```text
~/Documents/www/easy-cms/
```

The application name is:

```text
easy-cms
```

Do not ask for another name.

Do not create an `easy-cms` directory inside the existing `easy-cms` directory.

The current directory itself is the application root.

---

## Step 2 — Create the Next.js Application

Create the Next.js application directly in the current root directory.

Prefer `pnpm`.

Run:

```bash
pnpm create next-app@latest . --typescript --tailwind --eslint --app --src-dir --import-alias "@/*"
```

Always use `.` as the application destination.

Never run:

```bash
pnpm create next-app@latest <app-name>
```

Never create a child directory for the application.

Do not run `cd <app-name>` after installation because the current directory is already the application root.

Do not pin the Next.js version.

Always use `@latest`.

All subsequent commands must run from the same current root directory.

After Next.js finishes creating the application, remove the default root `README.md`:

```bash
rm -f README.md
```

The final application must not contain a `README.md` file in the project root.

---

## Step 3 — Install Formatting and Linting Dependencies

Install the required development dependencies:

```bash
pnpm add -D prettier prettier-plugin-tailwindcss eslint-config-prettier eslint-plugin-prettier eslint-plugin-simple-import-sort
```

Do not remove the ESLint or Next.js dependencies installed by `create-next-app`.

The final project must contain the packages required by the configurations, including:

```text
eslint
eslint-config-next
eslint-config-prettier
eslint-plugin-prettier
eslint-plugin-simple-import-sort
prettier
prettier-plugin-tailwindcss
```

Use versions compatible with the latest stable Next.js version.

Do not manually pin versions unless necessary to resolve an actual compatibility issue.

---

## Step 4 — Configure Prettier

Create this file in the application root:

```text
prettier.config.mjs
```

Use exactly:

```js
/** @typedef {import('prettier').Config} PrettierConfig */

/** @type {PrettierConfig} */

const config = {
  plugins: ['prettier-plugin-tailwindcss'],
  printWidth: 80,
  tabWidth: 2,
  useTabs: false,
  semi: false,
  singleQuote: true,
  quoteProps: 'as-needed',
  jsxSingleQuote: false,
  trailingComma: 'es5',
  bracketSpacing: true,
  arrowParens: 'always',
  endOfLine: 'auto',
  bracketSameLine: false,
}

export default config
```

Do not change these options.

---

## Step 5 — Configure ESLint

Create or replace this file in the application root:

```text
eslint.config.mjs
```

Use exactly:

```js
import { defineConfig, globalIgnores } from 'eslint/config'
import nextVitals from 'eslint-config-next/core-web-vitals'
import nextTs from 'eslint-config-next/typescript'
import prettier from 'eslint-config-prettier'
import prettierPlugin from 'eslint-plugin-prettier'
import simpleImportSort from 'eslint-plugin-simple-import-sort'

const eslintConfig = defineConfig([
  ...nextVitals,
  ...nextTs,
  {
    name: 'prettier',
    plugins: {
      prettier: prettierPlugin,
      'simple-import-sort': simpleImportSort,
    },
    rules: {
      'simple-import-sort/imports': 'error',
      'simple-import-sort/exports': 'error',
      'prettier/prettier': 'error',
      'react-hooks/set-state-in-effect': 'off',
      'react-hooks/static-components': 'off',
    },
    extends: [prettier],
  },
  globalIgnores(['.next/**', 'out/**', 'build/**', 'next-env.d.ts']),
])

export default eslintConfig
```

Do not alter, simplify, reorder, or extend this configuration unless explicitly requested.

---

## Step 6 — Package Scripts

Check the application's `package.json`.

Ensure at minimum these scripts exist:

```json
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start",
    "lint": "eslint .",
    "lint:fix": "eslint . --fix",
    "format": "prettier --write .",
    "format:check": "prettier --check ."
  }
}
```

Preserve other scripts created by Next.js.

---

## Step 7 — Format Project

Run:

```bash
pnpm format
```

This must format the initial Next.js project and allow `prettier-plugin-tailwindcss` to normalize Tailwind CSS classes.

---

## Step 8 — Validate ESLint

Run:

```bash
pnpm lint
```

If ESLint reports automatically fixable errors, run:

```bash
pnpm lint:fix
```

Then run:

```bash
pnpm lint
```

again.

Do not disable rules simply to make lint pass.

Investigate dependency or configuration problems instead.

---

## Step 9 — Validate Prettier

Run:

```bash
pnpm format:check
```

The command must finish successfully.

If formatting errors are found, run:

```bash
pnpm format
```

and validate again.

---

## Step 10 — Validate Build

Run:

```bash
pnpm build
```

The skill is not complete until the Next.js production build succeeds.

If the build fails, investigate and fix problems caused by installation or configuration before finishing.

---

## Expected Structure

The resulting project should resemble:

```text
./
├── public/
├── src/
│   └── app/
│       ├── favicon.ico
│       ├── globals.css
│       ├── layout.tsx
│       └── page.tsx
├── eslint.config.mjs
├── next.config.ts
├── package.json
├── pnpm-lock.yaml
├── postcss.config.mjs
├── prettier.config.mjs
├── tsconfig.json
└── ...
```

The exact files generated by the latest Next.js version may change.

Do not downgrade Next.js or force an older project structure to match this example.

## Completion Checklist

Before declaring the task complete, verify:

- Application name matches the current root directory name.
- Next.js was installed directly in the current root directory.
- No additional application directory was created.
- Root `README.md` does not exist.
- Latest stable Next.js was installed.
- TypeScript is enabled.
- App Router is enabled.
- `src/` directory is enabled.
- Tailwind CSS is installed.
- `prettier.config.mjs` exists in the application root.
- `eslint.config.mjs` exists in the application root.
- Prettier is installed.
- `prettier-plugin-tailwindcss` is installed.
- `eslint-config-prettier` is installed.
- `eslint-plugin-prettier` is installed.
- `eslint-plugin-simple-import-sort` is installed.
- ESLint configuration matches this skill.
- Prettier configuration matches this skill.
- `pnpm lint` succeeds.
- `pnpm format:check` succeeds.
- `pnpm build` succeeds.
